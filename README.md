# Master-Admission-Probability

Локальный симулятор на Python: оценка шансов поступления в магистратуру по **приоритетам зачисления** и **согласию на зачисление** (по данным публичных конкурсных списков).

## Дисклеймер

Это **неофициальный** инструмент для личного анализа. Он **не** является расчётом приёмной комиссии (ПК), вуза или Госуслуг и **не** гарантирует результат зачисления. Модель опирается на ваши выгрузки и допущения о согласиях. Решение о зачислении принимает только вуз.

Лицензия: [MIT](LICENSE).

## Как это работает

1. Загружаете конкурсные списки (Budget.xlsx MAGREPORTS и/или CSV).
2. Задаёте число бюджетных мест по программам (`seats.yaml`).
3. Указываете **свой** уникальный код поступающего.
4. Модель склеивает заявки по коду и симулирует зачисление по приоритетам среди тех, у кого есть согласие (или при допущениях сценария).

Ключевые режимы:

| Режим | Смысл |
|---|---|
| **ВПП** | «Сейчас»: зачисление только среди имеющих согласие |
| **ВПП + ваше согласие** | То же, но вы точно среди согласившихся |
| **ОВП** | Крайний случай: согласие как будто у всех в загруженных списках |
| **Monte Carlo** | Случайные согласия прочих → доля прогонов с вашим зачислением |

Сценарии согласий прочих: `auto` / `balanced` / `optimistic` / `pessimistic` (или ручная `P`).

## Типы входных данных

Положите файлы в `data/raw/` (каталог в git пустой; сырые выгрузки **не публикуются**).

### Budget.xlsx (MAGREPORTS)

Выгрузки вида `*_Budget.xlsx` («Бюджетные места»). Ожидаются типичные колонки списка: код поступающего, приоритет, баллы, согласие, статус участия и т.п. Имя программы и кампус читаются из заголовка файла.

### CSV (старый формат / Госуслуги)

CSV с колонками вроде уникального кода поступающего, программы, приоритета, баллов, согласия, статуса. Имя файла обычно содержит название программы и метку времени выгрузки.

### seats.yaml

Число мест (КЦП) по ключу программы. Пример структуры — `seats.example.yaml` (демо-имена). Локальный `seats.yaml` в git не попадает.

Опционально: сводный `.xls` с местами можно скормить `scripts/build_seats_yaml.py` (см. `data/raw/README.md`).

## Быстрый старт

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt

copy seats.example.yaml seats.yaml
# положите свои списки в data/raw/
```

### Streamlit

```bash
streamlit run app.py
```

### CLI

```bash
python -m admission_sim --me ВАШ_КОД --data data/raw --seats seats.yaml --monte-carlo 1000 --yes
```

Полезные флаги: `--include-pending` / `--no-include-pending`, `--scenario`, `--consent-p`, `--campus`, `--report`, `--yes`. Подробности: `python -m admission_sim --help`.

## Ограничения модели

- Согласие в правилах приёма — на вуз целиком; в данных оно одинаково по программам одного поступающего.
- Неполные приоритеты в выгрузках → модель может считать уход на «внешнюю» (незагруженную) программу.
- Автопарсинг сайтов вуза и Госуслуг **не поддерживается**.
- Не выкладывайте полные конкурсные списки и личные отчёты в публичный репозиторий.

## Этические рамки

- Списки публикуются обезличенно (код без ФИО).
- Инструмент для **личного локального** использования открытых сведений.
- Не обходите авторизацию и не снимайте данные массово с ЕПГУ.
- Не сопоставляйте коды с приказами (там ФИО) и не публикуйте «кто есть кто».

Это не юридическая консультация.

## Структура

