# Master-Admission-Probability

Локальный симулятор на Python: оценка шансов поступления в магистратуру по **приоритетам зачисления** и **согласию на зачисление** (по данным публичных конкурсных списков).

## Дисклеймер

Это **неофициальный** инструмент для личного анализа. Он **не** является расчётом приёмной комиссии, вуза или Госуслуг и **не** гарантирует результат зачисления. Модель опирается на ваши выгрузки и допущения о согласиях. Решение о зачислении принимает только вуз.

Лицензия: [MIT](LICENSE).

## Как это работает

1. Загружаете конкурсные списки (выгрузка `*_Budget.xlsx` и/или CSV).
2. Задаёте число бюджетных мест по программам (`seats.yaml`).
3. Указываете **свой** уникальный код поступающего.
4. Модель склеивает заявки по коду и считает зачисление по приоритетам среди тех, у кого есть согласие (или при допущениях сценария).

Ключевые режимы:

| Режим | Смысл |
|---|---|
| **Сейчас, с текущими согласиями** | Зачисление только среди уже подавших согласие. Это снимок «как сейчас»: кто ещё не согласился, в зачисление не входит |
| **Если вы подадите согласие** | То же, но вы точно среди согласившихся |
| **Если согласие подадут все** | Крайний случай: согласие как будто у **всех** в загруженных списках. Если здесь вы зачислены — место есть, даже когда соглашается каждый |
| **Случайные прогоны** | Много раз случайно решаем, кто из **неопределившихся** подаст согласие (по выбранному сценарию). Доля прогонов с вашим зачислением — оценка шанса. Это не крайний случай «согласие подадут все» |

Сценарии согласий **прочих без согласия** (уже согласившиеся всегда считаются согласившимися):

| Сценарий | Смысл |
|---|---|
| `auto` | Доли согласия среди людей **с известными баллами**. У конкурентов (кто занял бы место, если согласие подадут все) доля считается **отдельно по трети списка** — верх / середина / низ по месту на той программе, куда человек попадает в этом крайнем случае. Маленькая треть (меньше 15 человек) откатывается к общей доле конкурентов. Ожидание вступительных с 0 в файле в эти доли **не входит**. Не 100%: если победители крайнего случая уже все согласились, эту долю не копируем неопределившимся. Таблица в отчёте — снимок «уже согласились», а не прогноз, что оставшиеся ещё согласятся к дедлайну |
| `balanced` | Одна общая доля для всех без согласия, тоже по людям с известными баллами (100% только если это правда по этому пулу) |
| `optimistic` | Конкуренты соглашаются реже (лучше для вас) |
| `pessimistic` | Конкуренты соглашаются чаще, чем в `auto`, но **не все** (потолок 95%) |

Слайдер / флаг `--consent-p` подменяет сценарий одной вероятностью согласия для всех без согласия.

**Как модель считает зачисление.** Поступающие по очереди пробуют программы в порядке своего приоритета. На каждой программе остаются лучшие по месту в списке, пока хватает бюджетных мест; остальных выталкивают. Люди ниже вас занимают только оставшиеся места, если выше не согласились или ушли на другой приоритет — вытолкнуть вас они не могут. «Зачислено сейчас / свободно» — фактическая занятость среди уже подавших согласие. Счётчики «выше вас» — персональная картина: 1-й приоритет с согласием выше вас и те, кто выше вас остался на программе; зачисленные ниже вас показаны отдельно и не считаются конкурентами впереди. Если в данных нет части приоритетов или неизвестно число мест, модель считает уход «вне загруженных программ» — дальше по кампусам не пробует. Перед случайными прогонами один раз оценивается вероятность согласия у каждого без согласия; в каждом прогоне для прочих случайно «бросается монетка» (ваш код всегда с согласием). Можно ограничить расчёт **одной программой**: симулируются она и конкурсы, куда конкуренты могут уйти по более высокому приоритету — это быстрее, чем гонять все загруженные списки.

Кто ещё ждёт результаты вступительных, участвует **с баллами и местом из файла** (часто 0). Модель **не** подставляет будущие баллы и **не** считает, что такие заявки заполнят список пропорционально. В паспорте видно, сколько таких людей стоят выше вас на каждой программе.

Таблица «Абитуриенты выше вас без согласия» — **не** весь список выше вас: только без согласия и с пересечением ваших программ (кто выше сразу на нескольких — отдельная строка по каждой). Если вы сейчас не зачислены, по умолчанию видны только те, кто при согласии **остаётся на программе пересечения**; кто ушёл бы на другую программу или вовне, скрыт. Уже согласившиеся и так в зачислении «сейчас». Колонка «куда, если согласится» — пересчёт, если согласие подаст **только этот** человек (плюс уже согласившиеся), а не крайний случай «согласятся все». Случайные прогоны учитывают **всех** неопределившихся (и каскад других конкурсов), а не только видимые строки таблицы. «Зачислено сейчас / свободно» — фактическая занятость среди уже подавших согласие; для вашего шанса смотрите места минус «выше вас с согласием», а не свободные места. В веб-интерфейсе таблицу можно сузить по программам (по умолчанию — все ваши); для выбранной программы показываются люди выше вас именно на ней.

Случайные прогоны дают долю с обычной погрешностью от числа прогонов (при 1000 — около ±3%, если шанс близок к 50%). Неопределённость **сценария согласий** обычно больше этого шума: сравнивайте авто и пессимистичный, а не копите тысячи прогонов ради десятых долей процента.

## Типы входных данных

Положите файлы в `data/raw/` (каталог в git пустой; сырые выгрузки **не публикуются**).

### Budget.xlsx (выгрузка конкурсных списков)

Файлы вида `*_Budget.xlsx` («Бюджетные места», источник MAGREPORTS). Ожидаются типичные колонки списка: код поступающего, приоритет, баллы, согласие, статус участия и т.п. Имя программы и кампус читаются из заголовка файла.

### CSV (старый формат / Госуслуги)

CSV с колонками вроде уникального кода поступающего, программы, приоритета, баллов, согласия, статуса. Имя файла обычно содержит название программы и метку времени выгрузки.

### seats.yaml

Число бюджетных мест по ключу программы. Пример структуры — `seats.example.yaml` (демо-имена). Локальный `seats.yaml` в git не попадает.

Опционально: сводный `.xls` с местами можно скормить `scripts/build_seats_yaml.py` (см. `data/raw/README.md`).

## Быстрый старт

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt

copy seats.example.yaml seats.yaml
# положите свои списки в data/raw/
```

### Streamlit

```bash
streamlit run app.py
```

### CLI

```bash
python -m admission_sim --me ВАШ_КОД --data data/raw --seats seats.yaml --monte-carlo 1000 --yes
```

Полезные флаги: `--include-pending` / `--no-include-pending` (ожидание результатов вступительных испытаний), `--scenario`, `--consent-p` (вероятность согласия вручную), `--campus`, `--focus-program` (случайные прогоны для одной программы — быстрее), `--mc-workers`, `--report`, `--yes`. Подробности: `python -m admission_sim --help`.

### Случайные прогоны: время и точность

На полном датасете (~15k абитуриентов, все кампусы, ожидание вступительных испытаний включено, **4 ядра**):

| Прогонов | Время (ориентир) | Погрешность доли (± примерно 95% при шансе около 50%) |
|---:|---:|---:|
| 500 | ~10–20 с | ±4% |
| **1000** | **~20–40 с** | **±3%** |
| 2000 | ~40–80 с | ±2% |
| 5000 | ~2–4 мин | ±1% |

Фильтр `--campus` или `--focus-program` ускоряет расчёт. На полном вузе одна программа даёт примерно **×2**: симулируются конкурсы с известным числом мест, связанные приоритетами (~97 из 143), а не все списки. Неопределённость **сценария согласий** обычно больше, чем шум самих прогонов при 1000 и больше — **1000 прогонов** обычно достаточно; 5000 имеет смысл, если нужна точность ±1%.

## Ограничения модели

- Согласие в правилах приёма — на вуз целиком; в данных оно одинаково по программам одного поступающего.
- Неполные приоритеты в выгрузках → модель может считать уход на «внешнюю» (незагруженную) программу.
- Ожидание вступительных с 0 в файле не входит в оценку долей согласия; будущие баллы не угадываются.
- Автопарсинг сайтов вуза и Госуслуг **не поддерживается**.
- Не выкладывайте полные конкурсные списки и личные отчёты в публичный репозиторий.

## Этические рамки

- Списки публикуются обезличенно (код без ФИО).
- Инструмент для **личного локального** использования открытых сведений.
- Не обходите авторизацию и не снимайте данные массово с ЕПГУ.
- Не сопоставляйте коды с приказами (там ФИО) и не публикуйте «кто есть кто».

Это не юридическая консультация.
