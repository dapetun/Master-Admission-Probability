# Project

This repository contains a production-quality software project.

The goal is to build maintainable, readable and reliable software.

---

# Development Principles

- Readability is more important than micro-optimizations.
- Prefer improving existing code over creating new abstractions.
- Avoid duplicated logic.
- Keep implementations simple.
- Prefer production-ready solutions.
- Never leave temporary fixes or TODO placeholders.

---

# Workflow

Always:

1. Inspect the repository.
2. Understand the current architecture.
3. Make a short implementation plan.
4. Implement.
5. Review your own changes.
6. Fix discovered issues.
7. Update documentation if necessary.
8. Only then finish.

---

# Environment

Always use the project's virtual environment.

Never install packages globally.

Create a dedicated environment if needed.

---

# Git

Never:

- commit
- push
- merge
- create branches
- delete branches
- create releases

without explicit user approval.

Commit messages:

- Russian
- short
- informal

---

# Communication

Always communicate in Russian.

If requirements are unclear:

Ask instead of guessing.

Never silently make product decisions.
